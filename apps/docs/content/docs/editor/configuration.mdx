Notice the boundary:

- `selector` is the only required field.
- `document` and `user` describe what opens and who is acting.
- `onReady` marks the first safe moment to enable document actions.
- `onContentError` reports content and import errors. `onException` reports other runtime exceptions.

## Change one startup decision

Add `documentMode: 'suggesting'` to the configuration object, then reload the application. New edits are now recorded as
tracked changes instead of changing the document directly.

[Document modes](/editor/document-modes) explains the three modes and lets you run the same edit in each one.

## Change a running Editor

After `onReady`, prefer a runtime method when one exists:

| Change           | Runtime method                 |
| ---------------- | ------------------------------ |
| Document         | `replaceFile()`                |
| Document mode    | `setDocumentMode()`            |
| Zoom             | `setZoom()` or `setZoomMode()` |
| Measurement unit | `setMeasurementUnit()`         |
| Bookmarks        | `setShowBookmarks()`           |
| Formatting marks | `setShowFormattingMarks()`     |

To change `extensions` or `workerUrls`, call `destroy()` and create a new `SuperDoc`. Those fields are read only when the
Editor mounts. Recreating the Editor can reset selection and temporary interface state.
